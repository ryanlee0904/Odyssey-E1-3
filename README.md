# Mini NPU Simulator

## 1. 실행 방법

- **사전 요구 사항**: Python 3.8 이상 (외부 라이브러리 사용 없음)
- **실행 명령어**: 
    python main.py

- **모드 설명**:
  - **모드 1 (사용자 입력)**: 콘솔에서 3x3 필터 2개(A, B)와 패턴을 직접 입력하여 MAC 연산을 수행하고 결과를 확인합니다.
  - **모드 2 (JSON 로드 및 분석)**: data.json 파일을 로드하여 5x5, 13x13, 25x25 크기의 패턴을 일괄 판정하고, 크기별 연산 시간 측정 및 결과 요약을 확인합니다. data.json 파일은 main.py와 같은 디렉토리에 위치해야 합니다.

## 2. 구현 요약

- **라벨 정규화(Label Normalization)**: 외부 데이터나 사용자 입력에 존재하는 다양한 형태의 라벨(예: +, x, cross, X, CROSS)을 프로그램 내부에서 일관되게 처리하기 위해 normalize_label() 함수를 구현했습니다. 모든 라벨은 Cross와 X 두 가지 표준 라벨로 변환되어 판정 및 비교에 사용됩니다.
- **MAC 연산 구현**: 외부 벡터화 라이브러리(NumPy 등)를 배제하고, 순수 Python의 2중 for 반복문을 사용하여 위치별 곱셈 및 누적합을 직접 구현했습니다.
- **동점 처리 정책 (Epsilon)**: 부동소수점 연산에서 발생할 수 있는 미세한 수치 오차(예: 0.30000000000000004)로 인한 판정 오류를 방지하고자, 두 점수의 차이가 1e-9 미만일 경우 동점(UNDECIDED)으로 간주하는 are_scores_tied() 함수를 적용했습니다.

### 3. 결과 리포트

### 3.1. 실패 케이스 원인 분석
- **발생 상황**: data.json 분석(모드 2) 결과, 총 6개의 테스트 중 3개의 케이스(size_5_1, size_13_2, size_25_1)에서 FAIL이 발생했습니다.
- **원인 진단**: 실패한 케이스들의 실제 산출 점수를 보면, Cross 필터와 X 필터의 계산 결과가 미세한 부동소수점 오차(예: 0.9와 0.8999999999999999)만을 가질 뿐 사실상 동일한 값을 가졌습니다. 두 점수의 차이가 프로그램에 설정된 허용 오차 기준(< 1e-9)보다 작아 동점(UNDECIDED)으로 판정되었으나, JSON 스키마에 정의된 예상 결괏값(expected)과 일치하지 않아 최종적으로 FAIL 처리되었습니다.
- **해결 및 개선 방향**: 이는 데이터 스키마나 로직의 근본적인 오류라기보다, 부동소수점 한계를 방어하기 위해 도입된 보수적인 수치 비교(Epsilon) 정책 때문에 발생한 현상입니다. 실제 AI/NPU 환경에서는 이러한 모호한 패턴에 대해 필터 가중치를 재학습시키거나, 동점 임계값을 동적으로 조정하여 점수 격차를 유의미하게 벌리는 방식으로 개선할 수 있습니다.

### 3.2. 시간 복잡도 (Time Complexity) 분석
- 본 시뮬레이터의 MAC 연산 시간 복잡도는 O(N²) 입니다.
- **근거**: 입력 패턴과 판별 필터는 모두 N x N 크기의 2차원 숫자 배열입니다. MAC 연산을 완료하기 위해서는 두 배열을 겹친 뒤 모든 위치의 요소를 한 번씩 곱하고 더해야 합니다. 행(row) 방향으로 N번, 열(column) 방향으로 N번 순회하는 중첩 반복문이 필수적이므로 전체 연산 횟수는 정확히 N²번이 됩니다.
- **성능 측정 표 해석**: 성능 분석 결과를 보면, 패턴 크기가 5x5 (연산 25회), 13x13 (169회), 25x25 (625회)로 증가함에 따라 실제 측정된 평균 연산 시간(ms) 역시 N의 크기가 커질수록 연산 횟수 곡선과 유사한 2차 함수 형태로 급격히 증가하는 것을 확인할 수 있습니다. 이는 입력 데이터 크기에 따른 O(N²) 시간 복잡도 특성을 물리적 측정 시간으로 증명하는 결과입니다.
